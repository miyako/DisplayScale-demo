# Demo architecture

Two forms share one class. The class talks to the component; the forms only
display `Form` fields and route events.

```
MonitorBoard form ──event──▶ MonitorBoard/method.4dm ──▶ DisplayScene
ScaleLab form    ──event──▶ ScaleLab/method.4dm    ──▶ DisplayScene / Demo_Lab*
                                   │
                                   ▼
                     cs.DisplayScale.Display (component)
                                   │  Resources/bin/<os>/display-scale
                                   ▼
                     {protocol:2, platform, monitors[]} JSON
```

## DisplayScene

`Project/Sources/Classes/DisplayScene.4dm`

| Member | Purpose |
| --- | --- |
| `new()` | builds `cs.DisplayScale.Display` for the current OS, immediately runs `query()` |
| `query()` | `version()` + `monitors()`; stores result, elapsed ms, timestamp; rebuilds `rows` |
| `result` / `value` / `lastError` | raw component envelopes, never flattened |
| `rows` | collection of `{device, primary, scale, size, monitor}` for the list box |
| `selected` / `selectedIndex` | current row, used by detail card and Scale Lab prefill |
| `selectRow($row)` | matches by `device` (stable across refreshes) |
| `copyJSON()` | puts the untouched result envelope on the pasteboard |
| `probeCrossPlatform()` | queries the *other* target, records the prelaunch error |
| `detail()` | view model for the detail card: readout, device, 3 stat pairs, note |
| `mapHTML()` | full SVG document of `bounds`, primary marker and per-monitor labels |
| `labParams()` | Scale Lab inputs prefilled from the selected monitor |
| `bindForm()` | writes view models into `Form` and calls `OBJECT SET TITLE`/`LISTBOX SELECT ROW` |

Error policy: a failed query is data, not an exception. The card shows the code
and message, the list is empty, and the status line keeps the timestamp.

## Forms

Both forms are generated by `scripts/make_forms.py`; treat the script as the
source of truth and the `.4DForm` files as build output.

### MonitorBoard (`Project/Sources/Forms/MonitorBoard/`)

State lives in `Form`:

| Key | Type | Fed by |
| --- | --- | --- |
| `Form.scene` | object | form method `On Load` |
| `Form.rows` | collection | `bindForm()` → list box |
| `Form.selectedRow` | object | `bindForm()` ← `currentItemSource` of the list |
| `Form.logText` | text | append-only API log (`Char(13)` separated) |
| `Form.probeText` | text | cross-platform probe result |
| `Form.toast` | text | short feedback line |
| `Form.noteText` | text | local note; never fetched from the component |

Objects: list `monitorList`, readout `detailScale`, `detailDevice`,
`detailCaption`, stat pair groups `stat1…3`, note `detailNote`, badge
`platformBadge`, status `statusText`, log `apiLog`, probe output `probeText`,
map `Map` (web area), buttons `btnRefresh`/`btnCopy`/`btnProbe`/`btnLab`, `toast`.

### Scale Lab (`Project/Sources/Forms/ScaleLab/`)

`Form.lab` holds `{nativeWidth, pointsWidth, dpi, mac, win}`. `Demo_LabUpdate`
recomputes both formulas and rewrites labels; `Demo_LabHTML` renders the
to-scale preview; `LabVisual` is the web area. Presets are buttons with no data
source: `btnUseDisplay` (from scene), `presetRetina` (3024×1512), `presetMore`
(3024×1800), `presetWin125` (3840×1920 @120 dpi), `presetWin150` (3840×1920
@144 dpi).

Formulas shown:

* macOS: `nativeWidth ÷ pointsWidth × 100`
* Windows: `dpi ÷ 96 × 100`

## Project conventions

* Plain-text project: `tokenizedText:false`, so every `.4dm` file is reviewable.
* `Project/Sources/dependencies.json` is intentionally empty (see
  [docs/FINDINGS.md](../docs/FINDINGS.md) §1).
* `Project/Sources/menus.json` adds a **Demo** menu with the two windows; the
  startup method opens MonitorBoard.
* `styleSheets.css` carries the palette; form JSON sets geometry and classes.
